# CastBench 排行榜主页设计

## 目标

在现有 USTC-AGI Time Series 静态站点中新增 `cast-bench/` 页面，复用 CastMind 的蓝灰配色、研究型排版、粘性导航、圆角卡片和信息密度，构建一个可直接演示的多维时间序列模型排行榜门户。页面既要让访客在首屏快速看到模型排名，也要解释榜单背后的 Benchmark Dataset、指标体系、数据切分、复现规则和提交流程。

## 状态边界

当前页面是 CastBench 信息架构、评测协议和交互界面的首版实现，不代表已经完成全部模型复现实验。

- 页面内的模型分数统一标注为 `Protocol Demo` / `协议演示数据`。
- 演示分数用于验证排名、筛选、排序、详情和对比交互，不构成模型真实性能声明。
- 正式结果需经过配置、日志、预测文件和复现实验审查后，才能进入 `Verified` 榜单。
- FutureCast 作为情境感知任务与数据底座；CastBench 作为公开评测、结果聚合和能力剖析门户。

## 方案比较

### 方案一：论文式静态长页

沿用 CastMind 的说明文档结构，以长段落和静态表格介绍评测体系。实现简单，但不利于比较模型，也无法体现 Leaderboard 的产品价值。

### 方案二：纯数据仪表盘

首屏放满图表、筛选器和数据表格，弱化方法与数据集说明。交互效率高，但会偏离现有研究站点风格，也容易让演示结果被误解为正式结论。

### 方案三：研究主页与交互榜单融合（采用）

保留 CastMind 的研究主页视觉语言，以榜单作为首要内容，再用数据集、指标矩阵、评测协议和提交流程解释排名来源。该方案同时满足“快速比较”和“理解评测”的需求，并能自然承接 FutureCast。

## 信息架构

### 1. Hero 与状态说明

- 标题：`CastBench`
- 副标题：`多维时间序列基础模型评测与公开排行榜`
- 说明 CastBench 比较的不只是单一误差，还覆盖概率预测、趋势判断、情境理解、鲁棒性和效率。
- 展示版本、模型数、数据域数、核心维度数等概览。
- 用高可见状态条说明当前是协议演示版，所有分数均为示意数据。
- 主操作跳转到榜单，次操作跳转到评测协议和 FutureCast 数据页。

### 2. Leaderboard

- 顶部展示前三名摘要卡，突出综合分与能力标签。
- 控制栏支持：
  - 关键词搜索；
  - 领域筛选；
  - 模型族筛选；
  - 评测维度切换；
  - 一键重置。
- 表格列包含：
  - 排名；
  - 模型与模型族；
  - 综合分；
  - 点预测；
  - 概率预测；
  - 趋势判断；
  - 情境理解；
  - 鲁棒性；
  - 效率；
  - 结果状态。
- 点击指标表头可排序；当前排序通过 `aria-sort` 暴露给辅助技术。
- 每行支持打开模型详情，查看六个领域得分、能力长短板、规模/开放性和评测状态。
- 每行支持加入对比，最多选择三个模型；对比栏用同尺度横向条展示六个能力分数。
- 搜索或筛选无结果时显示明确空状态；按 `Escape` 清空搜索并关闭详情。

### 3. Benchmark Dataset

CastBench Suite 由三层数据轨道组成：

1. `General Forecasting Suite`：覆盖能源、交通、天气、金融等公开数值预测任务；
2. `FutureCast Context Suite`：覆盖天气、事件、政策、文本、业务规则等上下文证据；
3. `Stress Test Suite`：覆盖长预测窗口、分布漂移、极端事件、缺失情境和跨域迁移。

页面用六个领域卡片展示能源电力、交通出行、气象环境、金融零售、医疗运营与跨域困难集。每张卡片标明序列类型、情境来源、预测跨度和主要挑战，但不虚构尚未冻结的样本量或发布规模。

### 4. 评测维度与综合分

六个能力维度：

1. 点预测准确性；
2. 概率预测质量；
3. 趋势与转折判断；
4. 情境理解与证据利用；
5. 跨域鲁棒性；
6. 推理效率。

默认综合分采用透明权重：

`Overall = 30% Accuracy + 15% Probabilistic + 15% Trend + 20% Context + 15% Robustness + 5% Efficiency`

所有子分统一映射到 0–100。缺失维度不进行静默填补；正式总榜要求至少覆盖五个维度并完成所有必选数据域。页面明确显示权重和指标方向，防止把 MAE、CRPS 等“越低越好”的原始值直接与“越高越好”的能力分混淆。

### 5. 评测协议

- 时间顺序切分，禁止随机窗口泄漏；
- 未见实体、区域、事件和情境组合用于域外评测；
- 统一上下文长度、预测长度、采样预算和推理调用预算；
- 报告三个随机种子或确定性推理配置；
- 同时报告均值、最差数据域和覆盖率；
- 保存配置、预测文件、运行日志、环境信息与模型卡；
- `Demo`、`Submitted`、`Reproduced`、`Verified` 四级结果状态严格区分。

### 6. 提交与复现

以四步流程展示：

1. 选择评测轨道；
2. 运行标准适配器；
3. 上传结果包；
4. 复现审查后发布。

首版不添加真实提交接口；按钮明确标注“提交入口筹备中”，避免产生不可用操作。保留 FutureCast 和主页的有效站内链接。

## 视觉系统

- 复用站点最新的深海军蓝配色：`#091f44`、`#06162e`、`#17324d`、`#4c6176`、`#d5e3eb`、`#f4f7f9`，并加载共享响应式样式层。
- 首屏采用白到浅蓝渐变，突出 CastBench 品牌字样和排行榜定位。
- 主要内容最大宽度约 1180px，榜单比 CastMind 正文更宽，以保证指标列可读。
- 卡片使用 10–16px 圆角、细边框和克制阴影；排名只用金、银、铜作为局部状态色。
- 图形表达使用 CSS 条形、数字和文本，不引入外部图表库。
- 桌面端保持表格效率；窄屏允许榜单区域横向滚动，其余网格降为单列。
- 支持 `prefers-reduced-motion`、清晰焦点环和高对比文字。

## 组件边界

- `cast-bench/index.html`：页面结构、视觉样式、演示数据和无依赖交互。
- `tests/cast-bench.test.mjs`：内容、状态边界、语义结构、模型数据、交互钩子、响应式和站内入口契约。
- `index.html`：在 CastMind 项目卡中增加 CastBench 入口。
- `cast-mind/index.html`：在项目页粘性导航中增加 CastBench 入口，不改动用户现有文案调整。

## 数据与交互降级

- JavaScript 禁用时，Hero、数据集、指标、协议和提交流程仍可阅读；榜单区域提供静态说明。
- 页面不请求远程 API，不依赖远程字体和第三方脚本。
- 无匹配结果时保留筛选器并显示恢复操作。
- `HTMLDialogElement` 不可用时，详情面板使用普通可见区域回退。
- 表格超宽时只在榜单容器内滚动，不造成整页横向溢出。

## 验收标准

- 新页面可通过 `cast-bench/` 访问，并从主页 CastMind 卡片与 CastMind 项目页进入。
- 首屏清楚表达 CastBench 定位和演示状态。
- 榜单至少包含十种代表性模型/算法，支持搜索、领域、模型族、维度排序和重置。
- 可打开模型详情，并可选择最多三个模型进行多维对比。
- 页面包含三层数据轨道、六个领域、六个评测维度、权重公式、无泄漏协议和四步提交流程。
- 所有演示分数均有清晰免责声明，页面不声称其为正式复现结论。
- 键盘焦点、`aria-live`、`aria-sort`、对话框标签和 `Escape` 行为完整。
- 390px 宽度下除榜单内部外无页面级横向溢出；桌面端表格列清晰。
- `node --test tests/*.test.mjs`、HTML 内联脚本语法检查和 `git diff --check` 通过。

## 非目标

- 本轮不实现服务器、账户、数据库或真实在线提交。
- 本轮不抓取或宣称第三方模型的最新官方成绩。
- 本轮不发布、推送或部署远程站点。
- 本轮不重构全站导航或共享样式。
- 本轮不覆盖或提交用户在 `cast-mind/index.html` 与 `cast-claw/assets/` 中的既有改动。
