# 时间序列预测：预测智能页面设计

## 目标

将 `forecasting/` 从以技术路线和项目清单为主的展示页，重构为一页能够回答“时间序列预测是什么、为什么重要、难在哪里、完整系统应具备什么能力、研究组如何推进”的研究愿景页。页面必须保留现有代表性工作和应用入口，并与站点现有深海军蓝学术视觉系统一致。

## 内容原则

- 不把长篇提示正文逐段复制到网页，而是压缩为可扫描的网页叙事。
- 核心定义保持明确：时间序列预测是部分可观测、含噪、机制变化且情境不完全已知条件下的未来认知与提前决策过程。
- 同时表达状态认知、未来推断、决策支持三类问题。
- 不把点预测或平均误差当作完整答案；突出未来轨迹、概率、不确定性、约束、风险和决策价值。
- 保留现有六类技术方向、代表性工作与电力负荷入口，并补齐已存在的新能源和水文应用入口。
- 外部资料仅作为“参考与延伸”，不把综合判断伪装成官方结论。

## 页面结构

1. Hero：以“面向动态复杂系统的未来认知”为标题，展示输入证据、认知过程与输出决策的最小流程，并给出状态认知、未来推断、决策支持三个支点。
2. 页内导航：本质、价值、独特性、科学挑战、能力链、范式转变、研究版图。
3. 本质：解释预测不是普通回归或单纯外推，给出条件概率任务表达与“时间序列是复杂系统运行痕迹”的判断。
4. 价值：突出提前量、资源配置、风险预警、动态控制、系统韧性和科学认知，以及系统耦合、波动、决策频率和错误代价上升带来的迫切性。
5. 独特性：以六张卡片概括尚未发生的目标、部分观测、历史规律失效、联合未来轨迹、部分已知情境、不确定性与行动反馈。
6. 科学挑战：归纳为可预测性边界、状态与机制重建、时序语义、非平稳与长尾、联合一致性、可信评测与决策价值六个问题。
7. 能力链：将十二项能力压缩为九阶段闭环，并显式区分快速基础预测、按需慢思考和决策反馈。
8. 范式转变：完整保留提示中的六个“从……到……”方向。
9. 研究版图：保留六类技术路线和代表性工作，将其放到能力链之后作为研究落点；应用入口扩展为负荷、新能源和水文三类。
10. 参考与延伸：列出用户材料中的 WMO、Scientific Reports 和两项预印本链接，说明其对应的证据边界。

## 交互与响应式设计

- 继续使用现有静态 HTML、内嵌 CSS 和轻量原生 JavaScript，不增加构建依赖。
- 页内导航使用锚点和 `scroll-margin-top`，移动端允许横向滚动。
- 流程图使用语义化 HTML/CSS，而非位图，确保文字可选择、可检索并随屏幕重排。
- 桌面端采用 2–3 列卡片；960px、720px 和 480px 断点逐步降为单列。
- 保持当前全站导航改动，避免覆盖工作区中其他未提交内容。

## 验收标准

- 新增专门回归测试，覆盖核心定义、三类问题、五类价值、六项独特性、六个挑战、九阶段能力链、六个范式转变、现有研究成果和三个应用入口。
- 页面保留共享色板、响应式样式和有效的内联脚本。
- 本地完整测试通过，`git diff --check` 无空白错误。
- 本地静态服务器上验证桌面端和移动端无横向溢出，关键锚点、应用链接和导航菜单可用。
